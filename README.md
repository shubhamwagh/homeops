# homeops

Bare-metal [k3s](https://k3s.io) cluster provisioning using [k3sup](https://github.com/alexellis/k3sup) and Ansible. Supports N control-plane nodes (HA) and N worker nodes.

---

## Prerequisites

You need [mise](https://mise.jdx.dev) installed on your local machine. Everything else is managed by mise.

### Install mise

```bash
# macOS
brew install mise

# Linux
curl https://mise.run | sh
```

Then add mise to your shell:

```bash
# bash
echo 'eval "$(mise activate bash)"' >> ~/.bashrc

# zsh
echo 'eval "$(mise activate zsh)"' >> ~/.zshrc
```

## Quick Start

### 1. Install all tools

```bash
just tools
```

Installs via mise: `k3sup`, `kubectl`, `helm`, `ansible`, `gum`, `yq` (pinned in `mise.toml`).

> **Note:** On first run, `just` itself isn't available yet. Bootstrap with `mise install` first, then `just tools` works for subsequent use.

### 2. Configure your cluster

```bash
just configure
```

An interactive prompt (powered by [gum](https://github.com/charmbracelet/gum)) walks you through:

- Cluster name (used as kubeconfig context)
- SSH user, key path, port
- k3s version and cluster token (auto-generated if left blank)
- Extra server/agent args (defaults to a minimal install with flannel, traefik, servicelb, metrics-server, and cloud controller disabled — ready for your own CNI)
- Control-plane node IPs (space-separated — first is the bootstrap node)
- Worker node IPs (optional)
- Virtual IP for HA (required if >1 control-plane node)
- kubeconfig output path (default: `<repo>/kubeconfig`)

This writes two files (both gitignored):
- `k3s/inventory.yml` — Ansible inventory
- `k3s/group_vars/all.yml` — cluster variables

### 3. Provision the cluster

```bash
just install
```

Runs the Ansible playbook which:
1. Bootstraps the first control-plane node with `--cluster-init`
2. Joins additional control-plane nodes one at a time (serial, avoids etcd split-brain)
3. Joins all worker nodes in parallel
4. Waits until all nodes report `Ready`
5. Copies kubeconfig to `~/.kube/config`

After install, `kubectl` works without any extra setup:

```bash
kubectl get nodes -o wide
```

## All `just` Recipes

```
just tools            # install all required tools via mise
just configure        # interactive setup → writes inventory + group_vars
just install          # provision the full cluster
just add-node         # interactively join one new node (server or worker)
just teardown         # uninstall k3s from all nodes
just nodes            # kubectl get nodes -o wide
just helm-list        # helm list -A
just copy-kubeconfig  # copy kubeconfig from control-plane to ~/.kube/config
```

---

## Adding a Node

```bash
just add-node
```

Prompts for node type (`server` or `worker`) and IP, then joins the node to the running cluster. After joining, manually add the IP to `k3s/inventory.yml` so future playbook runs include it.

---

## Teardown

```bash
just teardown
```

Prompts for confirmation (`yes`), then uninstalls k3s in safe order:
1. Worker nodes
2. Secondary control-plane nodes
3. Init control-plane node (last)

Also removes the local kubeconfig file and `~/.kube/config`.

## HA Setup Notes

When using multiple control-plane nodes you need a Virtual IP (VIP) in front of all control-plane nodes. Common options:

| Tool | Notes |
|---|---|
| [kube-vip](https://kube-vip.io) | Runs inside the cluster, no extra infra |
| keepalived | Classic Linux VIP, runs on the nodes |
| External LB | HAProxy, nginx, cloud LB |

Set this IP as the VIP during `just configure`. It will be added as `--tls-san` automatically so the API server certificate is valid when accessed via the VIP.

## Default Server Args

The configure wizard defaults to a stripped-down k3s install:

```
--write-kubeconfig-mode=644
--disable=flannel,local-storage,metrics-server,servicelb,traefik
--flannel-backend=none
--disable-network-policy
--disable-cloud-controller
--disable-kube-proxy
```

This leaves the cluster ready for a CNI like [Cilium](https://cilium.io) which handles pod networking, network policy, load balancing, and kube-proxy replacement via eBPF.

## Project Structure

```
homeops/
├── mise.toml                   # tool version pins
├── Justfile                    # all operations exposed as just recipes
└── k3s/
    ├── ansible.cfg             # SSH pipelining, fact caching, yaml output
    ├── inventory.yml           # generated by just configure (gitignored)
    ├── group_vars/
    │   └── all.yml             # generated by just configure (gitignored)
    └── playbooks/
        ├── install.yml         # full cluster provisioning
        ├── add-node.yml        # join a single node
        └── teardown.yml        # uninstall everything
```
